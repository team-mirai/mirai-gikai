# Review

変更差分に対して、テストガイドラインチェックとコード品質チェックを実行するセルフレビュースキル。

## 使い方

引数なしで実行すると、develop ブランチとの差分をレビューする。

## ワークフロー

### Step 1: 差分の確認

まず現在のブランチと変更内容を確認する:

```bash
git branch --show-current
git diff --stat develop...HEAD
```

変更がない場合（かつ未コミット変更もない場合）は通知して終了。
未コミット変更がある場合は `git diff --stat` で確認する。

### Step 2: 変更ファイル一覧の取得

```bash
git diff --name-only develop...HEAD
```

未コミット変更がある場合は `git diff --name-only` も取得する。

### Step 3: テストガイドラインチェック

以下のルールを順番にチェックし、違反があれば報告する。

#### 3a. 純粋関数のテスト必須チェック
- `shared/utils/` や `server/utils/` に新規作成された `*.ts` ファイルに対応する `*.test.ts` があるか
- 対象: `git diff --name-only --diff-filter=A develop...HEAD` で追加されたファイルのうち `utils/` 配下のもの

#### 3b. DB function の統合テスト必須チェック
- `supabase/migrations/` に `CREATE.*FUNCTION` を含む新規マイグレーションがある場合、`tests/supabase/db-function/` に対応するテストファイルがあるか
- テストファイル名は `{function-name}.test.ts` の形式であること

#### 3c. mock 禁止チェック
- 新規・変更テストファイルに `vi.mock("server-only")` が含まれていないか

#### 3d. server-only チェック
- `server/` 配下の新規ファイルに `import "server-only"` があるか（コンポーネント・ローダー・リポジトリ等）

### Step 4: コード品質チェック

変更ファイルの内容を読み、以下の観点でチェックする。

#### 4a. 関数の複雑度・長さ
- 1つの関数やコンポーネントが長すぎないか（目安: 50行以上は分割を検討）
- ネストが深すぎないか（目安: 3段以上）
- 条件分岐が複雑すぎないか

#### 4b. 命名の明確さ
- 変数名・関数名が意図を正しく表現しているか
- 略語や曖昧な名前がないか
- 命名規約に従っているか（ファイル名: ケバブケース、コンポーネント: パスカルケース、関数: キャメルケース）

#### 4c. 重複・共通化
- 同じロジックが複数箇所に書かれていないか
- 既存のユーティリティで代替できる処理がないか

#### 4d. 型安全性
- `any` 型や型アサーション（`as`）を不必要に使っていないか
- `!`（non-null assertion）を安易に使っていないか

#### 4e. エラーハンドリングの一貫性
- エラーを握りつぶしていないか（空の catch ブロック等）

#### 4f. Feature ディレクトリ構成
- server/client/shared の境界が守られているか
- Server Components に `import "server-only"` があるか
- Client Components に `"use client"` が付与されているか

#### 4g. コンポーネント設計
- コンポーネントの責務が単一か
- UI 規約に従っているか（`<button>` 禁止、インライン SVG 禁止、インラインカラーコード禁止）

### Step 5: 結果の報告

結果をまとめて表示する:

```
## テストガイドラインチェック結果

### パス
- 純粋関数テスト: すべて対応済み

### 違反
- DB function テスト漏れ: `get_interview_statistics` のテストが存在しません

### 要確認
- `server/components/foo.tsx` に `import "server-only"` がありません

## コード品質チェック結果

### 指摘事項
- [重要] `get-sessions.ts`: 関数が80行超で複雑
- [改善推奨] `session-list.tsx`: Props のデフォルト値が不要
- [軽微] `types/index.ts`: union が長い

### 良い点
- 型定義が明確で型安全性が保たれている
```

## 重要度の分類

- **重要**: 保守性に大きく影響する。修正を強く推奨
- **改善推奨**: 修正するとコード品質が向上する。対応は任意
- **軽微**: 細かい改善点。対応は任意

## 注意事項

- レビュー対象はデフォルトで `develop` ブランチとの差分
- 既存コードの問題は指摘しない。今回の変更差分に含まれるコードのみを対象とする
- 過度な指摘は避ける。実質的に保守性・可読性に影響する点のみ報告する
