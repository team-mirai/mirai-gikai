# 情報アクセシビリティ参加導線レビュー

## 結論

公開画面の主要な参加導線をレビューし、参加を妨げる可能性が高い6件の障壁を修正対象として特定した。
この記録は開発中の参加導線レビューであり、WCAGまたはJISへの適合、準拠、認証を示すものではない。

## 対象範囲と証拠レベル

- 対象は `web` のホーム、議案詳細、意見一覧、公開レポートである。
- 基準としたソースは `develop` のコミット `d2245b06af788f47b039849872741075efe84847` である。
- 本番公開中の画面は `https://gikai.team-mir.ai/` と、その画面から到達できる議案関連ページで確認した。
- 証拠はソース確認、ChromiumでのDOM・算出スタイル・390px幅確認、Reactコンポーネントテストで構成した。
- `admin` は高リスク箇所の静的確認だけを行い、管理業務の完全な利用プロセスは対象外とした。
- AIチャット、公開中でないインタビュー、認証後画面、第三者コンテンツは完全な操作確認の対象外とした。
- スクリーンリーダー、音声入力、スイッチ入力、拡大表示を用いた人手確認は未実施である。

## 証拠付きで確認できた事項

### 修正前の観察

- ホームには `h1` がなく、見出し階層が `h2` から始まっていた。
- ホームではラベルのない `main` ランドマークが入れ子になっていた。
- 公開画面の共通レイアウトには本文へ移動するスキップリンクがなかった。
- 意見一覧のフィルタボタンは視覚的な選択状態を持つ一方、`aria-pressed` を持っていなかった。
- 意見一覧のフィルタ変更後も、回答件数を通知するライブリージョンがなかった。
- 意見一覧のフィルタボタンにはフォーカスリングを打ち消すクラスがあり、Chromiumの算出スタイルでもフォーカス輪郭を確認できなかった。

### `SCREEN-ARIA-*` 補助検査

- `SCREEN-ARIA-ROLE-PERMITTED` は、追加した `group` と `status` の役割を要素と文脈に照らして確認した。
- `SCREEN-ARIA-ATTRIBUTE-PERMITTED` は、`aria-label`、`aria-pressed`、`aria-live`、`aria-atomic` の利用箇所を確認した。
- `SCREEN-ARIA-REQUIRED-STATE-PRESENT` と `SCREEN-ARIA-VALUE-VALID` は、フィルタの選択状態が `true` または `false` で更新されることをコンポーネントテストで確認した。
- `SCREEN-ARIA-NAME-VALID` は、フィルタグループに用途別の名前を付け、各ボタンの可視テキストを名前として維持したことを確認した。
- `SCREEN-ARIA-NATIVE-HTML-PREFERRED` は、操作要素が共通 `Button` を介したネイティブの `button` であることを確認した。
- 以上は実装上の整合を示す補助検査であり、規格条項の合否には変換しない。

### 修正後のブラウザ確認

- 検証用の一時ページで `main` 1件、`h1` 1件、重複ID 0件を確認した。
- 「本文へ移動」はフォーカス時に固定表示され、選択時に `#main-content` へ移動して `main` がフォーカスを受けた。
- フィルタの「すべて」は初期状態で `aria-pressed="true"`、他の選択肢は `false` だった。
- 「期待」を選択すると同ボタンが `true` になり、回答件数は2人から1人へ変わり、対象の回答だけが残った。
- フィルタへキーボードフォーカスを置くと `:focus-visible` が成立し、5pxまでのリングを含むbox-shadowを確認した。
- 390px幅では文書全体の横あふれはなく、フィルタ行だけが意図どおり横スクロール可能だった。
- 検証用の一時ページは確認後に削除し、変更差分には残していない。

- `not_tested`: 実キーボードによるページ全体のTab順序は、ブラウザ自動操作でTab移動を再現できなかったため未確認である。
- 次の確認では、Chromeを実キーボードで操作し、スキップリンク、ヘッダー、主要操作、フッターの順序と逆順を確認する。
- `not_tested`: `status` と `aria-pressed` の実際の読み上げは支援技術を利用していないため未確認である。
- 次の確認では、WindowsのNarratorまたはNVDAとChromeを用い、選択状態と件数変更の通知内容、回数、順序を確認する。
- `not_tested`: 200パーセント拡大、400パーセント相当のリフロー、色コントラスト、タッチ操作は今回の証拠に含めていない。
- `not_tested`: 公開中でないインタビューを含む参加開始から送信完了までの完全なプロセスは、利用可能な対象がなかったため確認していない。
- `not_tested`: 修正後の本番環境は未デプロイであり、本番での効果は確認していない。

## 主張可能な範囲

主張できるのは、公開画面の主要な参加導線について6件の障壁をソースと実ブラウザの証拠で特定し、対応するコードと回帰テストを追加したことまでである。
WCAG、JIS、その他の規格への適合または準拠は主張できない。
規格プロファイルを固定した人手評価を実施していないため、評価JSONは生成していない。
監査記録は本ファイルを正本とする。
