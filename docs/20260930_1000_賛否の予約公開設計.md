# チームみらいの賛否・コメントの予約公開 設計

## 目的
議案に対するチームみらいの賛否（`mirai_stances.type`）とコメント（`mirai_stances.comment`）を、
管理画面で事前に登録しておき、指定した日時に公開サイトへ反映できるようにする。

## データモデル
`mirai_stances` にカラムを追加する。

| カラム | 型 | 意味 |
| --- | --- | --- |
| `publish_at` | `timestamptz NULL` | 公開日時。`NULL` は即時公開（既存行の挙動は変わらない） |

- 賛否とコメントは同じ行で管理しているため、公開日時も行単位（賛否＋コメントをまとめて公開）とする。
- 公開判定はバッチ処理でフラグを切り替えるのではなく、読み取り時に `publish_at <= now` で判定する。
  cron 等の追加インフラが不要で、指定時刻ちょうどに切り替わる。

## 公開判定
`@mirai-gikai/shared/mirai-stance/publish-schedule` の `isMiraiStancePublished(publishAt, now)` に集約する。

- `publishAt` が null → 公開
- `publishAt <= now` → 公開
- それ以外（未来・不正な日時）→ 非公開

## 公開側（web）の挙動
公開日時前の賛否は「賛否未設定」と同じ扱いにする（賛否カード非表示。`preparing` の議案は従来どおり「法案提出前」表示）。

| 経路 | 対応 |
| --- | --- |
| 議案詳細 `getBillById` | `unstable_cache`（10分）には賛否を生データのままキャッシュし、キャッシュ外で `hideUnpublishedStance` を適用する。キャッシュの有効期限を待たずに公開日時ちょうどに切り替わり、公開日時前の賛否がクライアントに送られることもない |
| オープンデータ API（一覧・詳細） | `publish_at` を select し、`toOpenDataMiraiStance` で公開日時前は `null` を返す |
| プレビュー `getBillByIdAdmin` | 管理者の確認用のため、公開日時前でも表示する |

なお、賛否はインタビュー・チャットのAIプロンプトには使用していないため、そちらの対応は不要。

## 管理画面（admin）
- 議案編集画面のスタンスフォームに「公開日時（任意・日本時間）」の `datetime-local` 入力を追加する。
  - 空欄 → `publishAt: null`（即時公開）
  - 入力値は日本時間として `YYYY-MM-DDTHH:mm:00+09:00` に変換して保存する（ブラウザのタイムゾーンに依存しない）
- 公開日時前のスタンスには「公開予約中: YYYY/MM/DD HH:mm」バッジを表示する。
- Server Action で `stanceInputSchema` による検証を行う。

## MCP（`upsert_mirai_stance` / `get_mirai_stance`）
- `publishAt`（ISO 8601、タイムゾーン付き）を受け付ける。`null` で即時公開、**省略時は既存の公開日時を保持**する。
  - Slack bot 等からコメントだけを更新した際に、予約が意図せず解除されて即時公開されることを防ぐ。
- `get_mirai_stance` は `publishAt` を返す。

## テスト
- `isMiraiStancePublished`、`hideUnpublishedStance`、`toOpenDataMiraiStance`、`toStanceColumns`、JST 変換関数の単体テスト
- オープンデータ詳細の統合テスト（公開日時前は null、経過後は返す）
- MCP 統合テスト（publishAt の保存・null で解除・省略時の保持）
