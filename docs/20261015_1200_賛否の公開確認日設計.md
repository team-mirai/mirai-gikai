# チームみらいの賛否の公開確認日 設計

## 目的
党内で決めた賛否と判断の理由を、管理画面に**非公開で**事前登録しておく。
委員会採決の予定日（公開確認日）になったら、Slack で政調会長に公開してよいかを確認し、
承認されたら公開する。

日次の確認・承認ボタンは mirai-gikai-content の Slack bot が担う
（設計: team-mirai/mirai-gikai-content `docs/design/2026-10-15-stance-scheduled-publish.md`）。
このリポジトリでは、データモデル・管理画面・MCP ツールを提供する。

## 公開日時（publish_at）との違い

| 項目 | `publish_at`（予約公開） | `publish_review_date`（公開確認日） |
| --- | --- | --- |
| 前提 | 公開（`is_published = true`） | 非公開（`is_published = false`） |
| 型 | `timestamptz` | `date`（JST の日付） |
| その日時になると | 人の操作なしで自動的に公開される | Slack で政調会長に公開確認が届く。承認されるまで非公開のまま |
| 用途 | 公開してよいことが確定している賛否の公開時刻を指定する | 委員会日程がずれる可能性があり、公開前に確認したい賛否 |

`publish_at` の意味（その時刻に自動公開）を変えないよう、別カラムにした。
非公開にすると `publish_at` はリセットされるが、`publish_review_date` は非公開が前提なので保持する。
公開すると確認は不要になるため、`publish_review_date` をリセットする。

## データモデル

| カラム | 型 | 意味 |
| --- | --- | --- |
| `publish_review_date` | `date NULL` | 公開確認日（JST）。非公開の賛否について、この日以降に Slack で公開確認を出す |

`update_mirai_stances_updated_at` トリガーは、`publish_review_date` だけが変わった更新では `updated_at` を更新しないようにした。
`updated_at` は「公開確認の後に内容が編集されていないか」の判定に使う。日付の変更は内容の変更ではないため、この判定に影響させない。

## 管理画面（admin）
- 「公開する」スイッチがオフのときだけ、「公開確認日（任意・日本時間）」の date 入力を表示する。
- 非公開で公開確認日がある賛否には「公開確認日: YYYY-MM-DD」バッジを表示する。

## MCP

| ツール | 内容 |
| --- | --- |
| `get_mirai_stance` | `publishReviewDate` と `updatedAt` を返すようにした |
| `upsert_mirai_stance` | `publishReviewDate` を受け付ける（`null` で解除、省略時は保持）。`isPublished: true` のときはリセットする |
| `list_mirai_stances_pending_review` | `{ onOrBefore }` 以前に公開確認日を迎えた非公開の賛否を、公開確認日の古い順に返す |
| `publish_mirai_stance` | `{ billId, expectedUpdatedAt }`。`updated_at` が一致し、かつ非公開の場合だけ公開する（条件付き UPDATE で atomic に行う）。失敗時は `{ ok: false, reason: "not_found" \| "already_published" \| "stale" }` |
| `update_mirai_stance_review_date` | `{ billId, publishReviewDate }`。非公開の賛否の公開確認日だけを更新する。失敗時は `{ ok: false, reason: "not_found" \| "already_published" }` |

`publish_mirai_stance` が `expectedUpdatedAt` を受け取るのは、Slack に確認メッセージを出した後に担当者が賛否や理由を編集していた場合、
政調会長が見ていない内容を公開しないためである。

## テスト
